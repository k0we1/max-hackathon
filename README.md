# Поговорим

Бот и мини-приложение для мессенджера MAX с двумя разговорными играми.

**Карточки для обсуждения.** Выбираете колоду под компанию (пара, друзья, семья, команда)
и настроение (лёгкое, глубокое, весёлое), потом обсуждаете вопросы по очереди. Можно включить
штрафные задания для тех, кто не хочет отвечать. Прогресс сохраняется, итоги встречи бот присылает
в чат и по желанию напоминает поиграть завтра.

**Тест на совместимость.** Двое отвечают на одни и те же вопросы одновременно, каждый на своём
телефоне. В конце каждый получает свой тип, а пара ещё и описание совместимости. Если партнёр
не пришёл, тест можно пройти одному.

Есть админка: статистика, пользователи и их игры, редактор колод, напоминания и рассылка.

Часть колод и тестов сделана к тематическим годам: 2025, Год защитника Отечества, и 2026,
Год единства народов России.

## Стек

- Node.js 22.18+ без фреймворков: встроенный `http`, TypeScript запускается напрямую
  (type stripping), зависимостей в рантайме нет.
- Фронтенд на React 19 и Vite, две точки входа: мини-приложение и админка.
- Хранилище: один JSON-файл `data/db.json`, пишется атомарно через временный файл.
- Связь с MAX: Bot API через long polling, запуск мини-приложения с подписью `initData`.

## Быстрый старт

```bash
npm install
npm run build        # собрать фронтенд в public/
npm run mock         # запустить без MAX, на фейковом API
```

Мок поднимает бэкенд на `:3000` и фейковый MAX API на `:3001`. В консоль он печатает ссылки,
которые открывают мини-приложение от имени двух игроков, Алисы и Бориса, с корректно подписанными
данными запуска. Так можно пройти совместный тест в двух вкладках. Сообщения бота и ссылки
на их кнопки тоже печатаются в консоль. Админка открывается на `http://localhost:3000/admin/`,
пароль `mock`.

С настоящим ботом:

```bash
cp .env.example .env   # вписать токен бота и пароль админки
npm run build
npm start
```

`npm run me` проверяет токен и выводит имя, username и ссылку на бота.

Для разработки фронтенда удобно держать `npm run mock` в одном терминале и `npm run dev`
в другом: Vite проксирует `/api` и `/admin/api` на бэкенд.

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Назначение |
|------------|-------------|--------------|------------|
| `MAX_BOT_TOKEN` | да | | Токен бота из кабинета MAX для партнёров |
| `ADMIN_PASSWORD` | нет | | Пароль админки. Без него админка выключена |
| `PORT` | нет | `3000` | Порт HTTP-сервера |
| `DATA_FILE` | нет | `data/db.json` | Путь к файлу с данными |
| `MAX_API_URL` | нет | `https://platform-api2.max.ru` | Адрес Bot API |

## Команды

| Команда | Что делает |
|---------|------------|
| `npm start` | Запускает бота, API и раздачу статики |
| `npm run build` | Собирает мини-приложение и админку в `public/` |
| `npm run dev` | Dev-сервер Vite для фронтенда |
| `npm run mock` | Запуск без MAX, на фейковом API |
| `npm run me` | Проверка токена бота |
| `npm run typecheck` | Проверка типов бэкенда и фронтенда |
| `npm test` | Сборка и сквозные тесты (`node --test`) |

## Структура

```
src/            бэкенд
  main.ts       точка входа
  app.ts        конфиг и сборка приложения
  bot.ts        команды, кнопки и уведомления бота
  game.ts       правила игр, таймеры, подсчёт результатов
  server.ts     API мини-приложения и раздача статики
  admin.ts      API админки
  auth.ts       проверка подписи initData
  max.ts        клиент Bot API
  store.ts      типы данных и JSON-хранилище
  content.ts    колоды, тесты и типы личности
web/            фронтенд
  src/miniapp   мини-приложение
  src/admin     админка
  src/shared    токены дизайна и общие утилиты
scripts/mock.ts фейковый MAX для локального запуска
test/           сквозные тесты
docs/           документация
igra.bpmn       схема процесса «Карточки» (BPMN, есть экспорт в SVG)
test.bpmn       схема процесса «Тест на совместимость»
DESIGN.md       дизайн-система
```
