# Архитектура

Один процесс Node.js делает три вещи: опрашивает Bot API MAX (long polling), отдаёт HTTP API
для мини-приложения и админки и раз в 15 секунд проверяет таймеры игр.

```
MAX (чат) ──long polling──► Bot ──► Game ──► Store (data/db.json)
                                     ▲
мини-приложение ──/api/*──► server ──┘
админка ──/admin/api/*──► admin ──► Store
```

- `Bot` (`src/bot.ts`) принимает события из чата, отвечает на команды и кнопки и шлёт
  уведомления: итоги, приглашения, паузы, напоминания.
- `Game` (`src/game.ts`) хранит все правила. Он не знает про MAX: сообщения отправляет через
  интерфейс `Notifier`, который реализует `Bot`. Поэтому игру легко тестировать с фейковым API.
- `Store` (`src/store.ts`) держит все данные в памяти и после каждого изменения сохраняет их
  в JSON. Запись атомарная: сначала во временный файл, потом `rename`. Позиция long polling
  (`marker`) хранится там же, так что после перезапуска бот не получает события повторно.

## Запуск мини-приложения

Бот не передаёт в мини-приложение состояние напрямую. Кнопка `open_app` несёт короткий
`payload`, который MAX отдаёт приложению как `start_param`. Префикс задаёт, куда вести пользователя:

| Префикс | Откуда | Что открывается |
|---------|--------|-----------------|
| `c_<token>` | `/cards`, кнопка «Карточки», напоминание | Каталог колод |
| `t_<token>` | `/test`, кнопка «Тест» | Каталог тестов |
| `s_<sessionId>` | «Продолжить игру» после выхода | Начатая партия в карточки |
| `j_<sessionId>` | Приглашение в тест, «Вернуться к тесту» | Сессия теста |
| `o_<testId>` | «Пройти одному» | Новый одиночный тест |

`token` в `c_` и `t_` указывает на запись `launch`: из какого чата и кем вызвана игра.
Через неё итоги приходят в тот же групповой чат, откуда начали.

## Авторизация

Мини-приложение шлёт в каждом запросе заголовок `X-Init-Data`, это строка данных запуска от MAX.
Сервер проверяет её по алгоритму из документации MAX (https://dev.max.ru/docs/webapps/validation): HMAC-SHA256 с ключом, выведенным из токена
бота, сравнение за постоянное время, срок жизни 24 часа (`src/auth.ts`). Из этих данных берутся
пользователь, чат и `start_param`. Без валидной подписи API отвечает 401.

Админка работает по паролю из `ADMIN_PASSWORD`: он передаётся как `Authorization: Bearer <пароль>`,
на сервере сравниваются SHA-256 хеши за постоянное время.

## Карточки

1. Пользователь выбирает колоду и решает, включать ли штрафы. Порядок карточек перемешивается.
2. «Обсудили» отмечает карточку. Если штрафы включены, после каждой карточки показывается
   случайное штрафное задание из колоды.
3. «Выйти и сохранить» ставит партию на паузу, бот присылает кнопку «Продолжить игру».
4. После 10 минут без действий партия тоже встаёт на паузу.
5. Когда карточки кончились, бот присылает итоги (сколько обсудили, сколько штрафов, сколько
   минут) с кнопкой «Поделиться» и спрашивает, напомнить ли завтра. Напоминание повторяется
   каждые 24 часа, пока его не удалят в админке.

Колода копируется в сессию при старте, поэтому правка колоды в админке не ломает начатые игры.

## Тест на совместимость

1. Инициатор выбирает тест. Бот присылает в чат приглашение с кнопкой «Присоединиться».
2. На ответ партнёру даётся 5 минут, потом сессия истекает. Через 15 минут после создания бот
   предлагает пройти тест одному.
3. Когда двое в сессии, они отвечают на один и тот же вопрос. Следующий вопрос открывается,
   когда ответили оба. Мини-приложение опрашивает состояние сессии.
4. Если игрок свернул приложение, тест встаёт на паузу, а бот зовёт его обратно.
5. Если за 2 минуты никто не ответил на вопрос, тест завершается с частичным результатом.
   Если игрок вышел, результат тоже частичный.
6. Результат: у каждого варианта ответа есть веса по типам, побеждает тип с наибольшей суммой.
   Для пары берётся описание совместимости по ключу из двух типов.

Тесты бывают парные (`joint: true`) и одиночные.

## Таймеры

Все сроки заданы константами в начале `src/game.ts` и проверяются в `Game.tick()`:

| Константа | Значение | Что происходит |
|-----------|----------|----------------|
| `CARD_IDLE_MS` | 10 мин | Партия в карточки встаёт на паузу |
| `JOIN_TIMEOUT_MS` | 5 мин | Приглашение в тест истекает |
| `SOLO_OFFER_MS` | 15 мин | Бот предлагает пройти тест одному |
| `ANSWER_TIMEOUT_MS` | 2 мин | Тест завершается с частичным результатом |
| `REMINDER_INTERVAL_MS` | 24 ч | Период напоминаний |

## Контент

Колоды, тесты и типы личности лежат в `src/content.ts`. Колоды из этого файла попадают в базу
только при первом запуске, дальше их правят через админку. Тесты читаются из кода всегда,
в админке их можно только посмотреть.

У колоды есть тема (`couple`, `friends`, `family`, `team`), настроение (`light`, `deep`, `fun`),
список карточек, список штрафов и флаг `archived`, который прячет колоду из каталога.

## Тесты

`test/e2e.test.ts` поднимает приложение целиком на фейковом MAX API и проходит сценарии через
HTTP: подпись `initData`, полная партия в карточки со штрафами и напоминанием, совместный тест
с паузой и таймаутами, одиночный режим, админка. Время двигается вызовами `game.tick()`
с нужной меткой, реального ожидания нет.
