# Деплой

Приложение собирается в Docker-образ и запускается через Docker Compose.

## Образ

`Dockerfile` двухэтапный. Первый этап ставит зависимости и собирает фронтенд через Vite.
Во второй попадают только `src/`, `package.json` и собранный `public/`: в рантайме
npm-зависимости не нужны.

В образ добавлен корневой сертификат Минцифры: без него Node.js не доверяет TLS
у `platform-api2.max.ru`. Сертификат скачивается при сборке, его SHA-256 отпечаток сверяется
с зафиксированным в `Dockerfile`, и путь к нему передаётся через `NODE_EXTRA_CA_CERTS`.
Локально ту же задачу решает флаг `--use-system-ca` в `npm start`, если сертификат
установлен в системе.

Контейнер работает от пользователя `node`, healthcheck раз в 30 секунд запрашивает главную страницу.

## Запуск

```bash
cp .env.example .env    # MAX_BOT_TOKEN и ADMIN_PASSWORD
docker compose up -d --build
```

`docker-compose.yml`:

- читает переменные из `.env` и, если есть, из `admin.vars` (удобно держать пароль админки
  отдельно от токена);
- слушает только `127.0.0.1:${APP_PORT:-8092}`, наружу приложение выставляется через обратный
  прокси с TLS;
- монтирует `./data` в `/app/data`, там лежит `db.json`.

Пример для Caddy:

```
example.ru {
    reverse_proxy 127.0.0.1:8092
}
```

## Настройка в MAX

1. Создать бота в кабинете MAX для партнёров и получить токен.
2. Прописать у бота адрес мини-приложения: корень домена, например `https://example.ru/`.
3. Запустить приложение и проверить `npm run me` или логи контейнера: при старте в них
   выводятся имя и username бота.

Команды `/start`, `/cards` и `/test` бот регистрирует сам при запуске.

## Обновление

```bash
docker compose up -d --build
```

Данные в `data/db.json` переживают пересборку. Незавершённые партии и тесты продолжаются,
long polling продолжает с сохранённой позиции.

## Резервная копия

Всё состояние в одном файле, его достаточно копировать:

```bash
cp data/db.json backup/db-$(date +%F).json
```

Пишется файл атомарно, поэтому копия не окажется обрезанной на середине записи.
